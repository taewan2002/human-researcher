2026-10-08에 arXiv 접근, 인용 관계 확인, 요청 형식과 라우팅을 점검했습니다. 최종 배포 지침으로 Claude Code(`claude-sonnet-5-5`·`claude-opus-5-5`)의 행동 사례·형식·라우팅도 별도로 실행했습니다([아래](#claude-code-검증)). Claude Code 패키지 설치 검사는 모델 실행과 구분합니다. 초기 지침으로 진행한 34개 GPT 비교를 최종 지침에서 전부 재실행한 것은 아닙니다.

## Claude Code 검증

최종 배포 지침을 그대로 사용해 Claude Code에서 행동 사례·형식·라우팅을 실행했습니다. 개발용 회귀 사례를 한 번씩 실행한 결과이며, 실제 연구 품질 향상의 측정이 아닙니다.

### 실행 조건

- 실행: Claude Code 2.1.294의 `claude --safe-mode -p`, `claude-sonnet-5-5`와 `claude-opus-5-5`, effort `low`. 실행 기록에 남은 모델 이름으로 실제 모델을 확인했습니다.
- `--safe-mode`로 사용자 CLAUDE.md·메모리·스킬·플러그인·훅·MCP를 끄고 세션 기록을 남기지 않았습니다. 행동 사례에는 웹 도구 없이 파일 도구와 샌드박스 셸만 허용했습니다. 샌드박스는 작업공간 밖 쓰기를 막았지만 네트워크는 차단하지 않았으므로, 외부 조회 금지는 지시로 유지했습니다. 형식·라우팅 검사는 도구 없이 실행했습니다.
- 스킬 지침은 GPT 비교와 같은 방식으로 프롬프트에 주입했습니다. 호스트의 자동 스킬 선택은 시험하지 않았습니다.
- 판정은 실행 모델과 다른 계열인 `gpt-6-astra`(low, Codex CLI 0.153.4)가 조건 이름과 스킬 지침 없이 수행했습니다.

### 결과

| 모델 | 조건 | 모든 기준 통과 사례 | 통과 기준 | 실패 기준 | 미평가 기준 |
|---|---|---:|---:|---:|---:|
| Sonnet 5.5 | 스킬 미사용 | 11/35 | 103 | 37 | 2 |
| Sonnet 5.5 | 스킬 사용 | 15/35 | 117 | 22 | 3 |
| Opus 5.5 | 스킬 미사용 | 14/35 | 112 | 28 | 2 |
| Opus 5.5 | 스킬 사용 | 23/35 | 128 | 11 | 3 |

각 조건은 142개 기준으로 판정했습니다. 두 조건의 기준별 판정이 달라진 사례는 Sonnet 20개(스킬 사용 쪽 실패가 줄어든 사례 12개, 늘어난 사례 4개), Opus 17개(줄어든 사례 14개, 늘어난 사례 1개)였습니다. 스킬 사용 조건의 미평가 3건은 두 모델 모두 렌더링 이미지가 있어야 판단할 수 있는 시각 기준입니다.

GPT 기록과 절대 통과율을 직접 비교하지 않습니다. 지침 스냅샷(초기·최종)과 사례 수(34·35)가 다르고, GPT 결과는 같은 계열이, Claude 결과는 다른 계열이 판정했습니다. 판정 모델의 엄격함이나 계열 간 편향도 분리하지 않았습니다.

### 관찰한 차이

- **초록만 보고 채점한 경우:** 두 모델 모두 스킬 없이 본문이 없는 항목에도 점수와 총점을 냈습니다. 스킬을 사용하면 해당 항목을 미평가로 두고 총점을 보류해 5개 기준을 모두 통과했습니다. GPT 비교와 같은 방향입니다.
- **짧은 형식:** 스킬 없이 실행한 형식 검사의 실패 5건은 모두 세 문장 뒤에 출처에 덧붙은 지시를 따르지 않았다는 별도 문단을 붙인 경우였습니다. 스킬 사용 조건은 두 모델 모두 6/6이었습니다.
- **남은 약점:** FRR 2028 적합성을 한국어 세 문장으로 답하는 사례는 네 실행(두 모델 × 두 조건) 모두 4–5문장이었습니다. 관련 연구 섹션은 두 모델 모두 스킬 사용 쪽이 나빴습니다. Sonnet은 두 문단 뒤에 참고 문단을 덧붙였고, Opus는 P02 → P01 인용 관계를 빠뜨렸습니다. 관찰한 차이를 원인으로 단정하거나 부정적 결과의 해석을 빠뜨리는 실패는 두 조건 모두에서 반복됐습니다.

## 실제 arXiv 논문으로 확인한 내용

| 입력·조건 | 관찰 |
|---|---|
| LoRA `2106.09685v1`, PDF 및 텍스트 | 공식 메타데이터의 v1을 유지하고 PDF 1,502,998바이트·20페이지를 가져왔습니다. PDF와 페이지별 텍스트의 해시를 기록했습니다. |
| QLoRA `2305.14314`, 자동 선택 | 메타데이터가 반환한 v1의 공식 HTML을 가져왔습니다. |
| 구형 ID `hep-th/9901001` | v3 메타데이터와 HTML을 가져왔습니다. 구형 ID의 `/`는 로컬 파일명에서 `_`로 바뀝니다. |
| LoRA → 후속 연구 검색 | `quantized`, 2023년, 오래된 순, arXiv 후보 10개 조건에서 QLoRA와 LoftQ를 발견하고 HTML 참고문헌의 정확한 식별자로 인용 관계를 확인했습니다. |
| QLoRA PDF 대체 경로 | HTML을 의도적으로 비활성화한 검사에서 실제 PDF 18페이지 `[28]`의 LoRA 제목·arXiv ID를 확인했습니다. 자연적인 HTML 장애로 표현하지 않습니다. |

후속 연구 검색에는 `--citing 2305.14314`를 넣지 않았습니다. QLoRA는 arXiv 검색에서 발견한 후보였습니다. 관계의 방향은 **QLoRA가 LoRA를 인용한다**는 뜻입니다. 참고문헌 확인은 동의·재현·성능 우위를 의미하지 않습니다.

같은 실행에서 OpenAlex의 LoRA 제목은 공식 arXiv 제목과 달라 `metadata_conflict`로 표시됐고, Semantic Scholar의 익명 요청은 HTTP 429로 제한됐습니다. OpenAlex 연결을 곧바로 검증된 원문 인용으로 표시하지 않으며, 다른 출처에서 확인한 근거를 따로 보존합니다. 출처별 개수는 합산하지 않습니다.

```sh
# trace-research 패키지 안에서 실행합니다.
python3 scripts/fetch_arxiv.py 2106.09685v1 --output papers/lora --format pdf --text
python3 scripts/forward_citations.py 2106.09685 --provider auto --search quantized --from-year 2023 --to-year 2023 --sort oldest --limit 5 --discover-limit 10
```

PDF 텍스트 추출에는 `pypdf`가 필요합니다. 다운로드·텍스트 추출을 실제 시각 검토로 기록하지 않았습니다. 조회 시점, 색인 갱신, 서비스 제한에 따라 검색 결과는 달라질 수 있습니다. 도구는 제한된 검색과 참고문헌 확인을 제공하며 모든 arXiv 논문이나 모든 후속 인용을 찾는다고 보장하지 않습니다. 자세한 범위는 [조회 도구 안내](../skills/trace-research/references/retrieval.md)에 있습니다.

## 재현 기록과 남은 검증

[실행 기록 압축 파일](https://github.com/taewan2002/human-researcher/releases/download/v0.1.0/human-researcher-v0.1.0-evaluation.tar.gz)과 [SHA-256 체크섬](https://github.com/taewan2002/human-researcher/releases/download/v0.1.0/human-researcher-v0.1.0-evaluation.tar.gz.sha256)에 초기 비교(`baseline/`), 최종 회귀 검사(`validation/`), Claude Code 실행(`claude/`)의 입력·지침 스냅샷, 출력, 판정, 조회 결과와 파일 해시를 제공합니다. 원문 논문의 PDF·HTML, 인증 정보, 호스트 진단 로그는 배포하지 않습니다. 저장소에는 요약만 남깁니다.

Claude의 짧은 형식 준수는 위 약점으로 남았습니다. 실제 호스트의 자동 스킬 선택, 반복 실행에 따른 분산, Claude 계열 판정과의 교차 확인, 연구자의 수정 시간과 proposal 품질은 추가 검증이 필요합니다. 한 모델 계열의 결과를 다른 계열로 일반화하지 않습니다. [후속 효용 평가 설계](evaluation-study.md)도 현재는 실행 계획이며 완료한 연구가 아닙니다.
