# 배포와 버전 관리

[설치 안내](installation.md) · [검증 범위](evaluation.md)

Human Researcher는 연구 스킬 7개와 사용 안내 1개를 하나의 버전으로 배포합니다. `VERSION`과 각 `SKILL.md`의 `metadata.version`은 같아야 하며 검증기가 이를 확인합니다.

- 첫 정식 배포는 `v0.1.0`입니다. 초기 공개를 정리하는 과정에서 2026-10-09 사용자 요청으로 arXiv 개선, 연구 견적·해석 지침, 안내 스킬과 Claude 검증을 정리했으며, 같은 날 추가 요청으로 HTML 읽기 화면·근거 링크·시각적 설명 개선과 RetoVLA proposal·VLA taxonomy 예제까지 합쳐 다시 하나의 초기 커밋으로 정리했습니다. 추가 피드백에 따라 지침 압축·요청 범위·출처 표기·isolated CLI 실행을 보완하고 릴리스 설명과 첨부 기록도 갱신했습니다. 이전 v0.1.0과의 구분에는 태그 이름뿐 아니라 커밋과 파일 해시를 사용합니다. 이후 태그는 검증한 커밋을 고정하며 다른 내용으로 옮기지 않습니다.
- 사용자 동작에 영향을 주는 수정은 변경 기록과 함께 다음 버전으로 배포합니다. 초기 `0.x` 단계에서는 호환성에 영향을 주는 변경을 명시합니다.
- 일반적인 README 문구 수정은 커밋으로 기록할 수 있습니다. 모든 문서 수정마다 새 Release를 만들 필요는 없습니다.
- 배포 이후에는 커밋 이력을 보존합니다. 기여 PR은 변경 이유를 유지하면서 squash merge할 수 있습니다.

## 배포 전 확인

1. 구조 검사·단위 테스트와 두 에이전트의 임시 설치를 실행합니다.
2. 바뀐 동작과 가까운 행동 사례를 실제 모델로 확인합니다. 전체 효과 비교에서는 동일 입력·모델·도구 조건을 유지하고, 판정 기준을 실행 모델에 주지 않습니다.
3. description 변경 시 라우팅 평가를 실행합니다. 성공 사례 수와 평가하지 못한 내용을 함께 기록합니다.
4. 문서·버전·설치 대상·변경 기록을 맞추고, 배포 커밋에 annotated tag를 만듭니다.
5. GitHub Release를 공개한 뒤 태그 URL에서 다시 설치해 파일 일치를 확인합니다.
6. 릴리스의 `target_commitish`와 태그가 가리키는 커밋을 맞춥니다. 평가 첨부 파일에는 당시 스냅샷의 커밋과 현재 배포본과의 관계를 명시하고, 안내문을 수정하면 내부 파일 해시와 압축 파일 체크섬도 갱신합니다. 과거 실행 결과와 당시 스킬은 그대로 보존합니다.

사용자는 설치 기록의 저장소·태그·커밋·파일 해시로 배포본을 식별할 수 있습니다. 업데이트와 이전 버전 복구는 현재 파일을 기록된 기준과 비교해 로컬 수정을 보존합니다. 모델 출력의 동일성은 버전 고정만으로 보장되지 않으므로 평가에는 모델·날짜·입력·도구·실행 기록도 필요합니다.
