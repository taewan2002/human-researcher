# 연구 효용 평가의 사전 설계

이 문서는 아직 실행하지 않은 후속 평가의 설계입니다. 현재 공개한 개발용 회귀 사례와 구분합니다.

## 확인할 질문

같은 자료·모델·도구·시간 예산에서 스킬을 사용하면, 연구자가 근거를 확인하고 실행 가능한 proposal을 만드는 데 필요한 수정 부담이 줄어드는지 확인합니다. 보기 좋은 문서나 높은 자체 점수를 주된 성과로 삼지 않습니다.

## 과제와 비교 조건

- 개발에 사용하지 않은 공개 논문 묶음과 연구 질문을 사전에 고정합니다. 인용 누락·유사 제목·버전 차이·분류의 중복·자원 제약처럼 실제 판단이 필요한 사례를 포함합니다.
- 연구자가 작성한 자연어 요청을 사용합니다. description을 복사한 요청이나 기대 답을 알려 주는 원자료는 제외합니다. 선택 기준과 제외 사례를 공개합니다.
- 같은 모델의 스킬 사용·미사용 조건을 비교하고 실행 순서를 섞습니다. 최소 두 모델 계열을 각각 반복 실행하며, 모델 이름·버전·시점·예산을 기록합니다. 한 계열을 실행하지 못했다면 그 비교는 미실행으로 남깁니다.
- 실행 전에 입력·판정 기준·반복 횟수·실패 처리 방법을 고정합니다. 평가 결과를 본 뒤 지침을 고치면 새 버전과 새 과제로 다시 검증합니다.

## 측정과 판정

| 측정 대상 | 관찰할 값 |
|---|---|
| 근거 정확성 | 주장과 실제 원문 위치의 일치, 잘못된 인용 연결, 읽지 않은 본문에 대한 주장 |
| 연구 설계 | 핵심 가설을 구별하는 비교·지표·실패 조건의 유무와 실제 제약 충족 |
| 연구자 수정 부담 | 중요한 오류를 고치는 시간, 수정 횟수, 최종 결정을 내리는 시간 |
| 설명 가능성 | 연구자가 선택 이유·대안·기각 조건을 자기 말로 설명할 수 있는지 |
| 요청 준수 | 길이·언어·형식·요청 범위 준수 여부 |

주요 평가는 조건을 가린 독립적인 사람 검토자가 원문과 함께 수행합니다. 모델 판정은 보조로 사용하며 사람 판정과의 불일치를 남깁니다. 전체 성공률뿐 아니라 조건별 짝지은 차이, 변동 범위, 공통 실패와 개별 반례를 공개합니다. 실패·미평가·제외 사례를 삭제하지 않습니다.

정해진 기준을 양쪽 모두 통과한 사례는 회귀 안정성의 근거로 남깁니다. 점수 차이가 나는 사례만 골라 일반적인 효용으로 소개하지 않습니다. 실제 연구자가 자신의 계획을 이해하고 방어할 수 있는지까지 확인하기 전에는 연구 품질 향상을 주장하지 않습니다.
