# A proposal the reader can see

Compose the argument before styling: **need → proposed change → informative test → possible decisions**. Adapt to the requested audience, language, format, and size. Show relationships, not only prose in equal-sized boxes.

## Choose useful visuals

- **Position:** a branching taxonomy, field → families → subfamilies → methods/papers, with consistent split criteria, justified multiple parents, and visible unknowns. Place the proposed method beside its closest supported neighbor. Two papers may justify a comparison, not a field taxonomy. A matrix does not replace a requested tree.
- **Change:** inputs, mechanism, outputs, and fixed conditions. Distinguish extra information from a method change; label arrows as data flow, dependency, or hypothesized influence.
- **Test:** controls and measures linked to beneficial, adverse, negligible, or inconclusive outcomes and next decisions.
- **Feasibility:** dependencies and decision milestones. Use measured or explicitly conditional durations.

For a dense map on a poster, show a legible relevant subtree and label omitted scope. Create a separate full map only when requested.

## Preserve meaning

Distinguish reported evidence, proposed work, and unknowns with text and line styles as well as color. Carry material qualifications into the visual. Empty categories do not establish novelty; arrows do not establish causation. Preserve source ambiguity instead of inventing more specific labels.

Without results, show the measurement plan or labeled result slots, not invented effect sizes, heatmaps, confidence intervals, or success bars. Any useful hypothetical illustration must be unmistakably labeled.

Follow [source evidence](source-evidence.md) for recognizable citations and portable links. Keep detailed evidence in an accessible source section instead of shrinking it beyond readability.

## Produce and inspect

For a requested poster, the optional [HTML template](../assets/proposal-poster.html) provides editable SVG and print styles. Adapt or remove sections. A3 landscape is a possible starting size only when none was specified. Prefer a prominent question, dominant comparison diagram, supporting evaluation, and compact sources. Use hierarchy, grouping, and whitespace before reducing font size; keep labels and citations readable at delivery size.

Deliver an editable, viewable artifact in the requested format; HTML/SVG may satisfy both. Export PDF when requested, then verify actual pages and dimensions with the checker linked in SKILL.md. Extra editors, download interfaces, separate source formats, uploads, and paid jobs require a task need and appropriate authorization.

Render and inspect readable and whole-page views. Repair clipping, overlap, missing glyphs, unreadable citations, and unclear arrows; keep a text alternative for SVG. Reconcile labels, counts, source qualifiers, and observed/planned status with prose. Remove placeholders and check source targets. If rendering is unavailable, state that precise limit rather than claiming visual verification.
