# 요청 범위·출처·템플릿 정리 검증

2026-10-09에 지침을 압축하고 출력 범위와 URL 출처를 명시했습니다. README의 제작자 소개도 제거했습니다. 이 기록은 개발용 회귀 검사이며, 스킬 유무의 효과 비교나 연구 품질 검증이 아닙니다.

## 변경한 동작

- 8개 패키지의 공통 첫 문장에 요청 범위와 출력 개수 확인을 넣고, 요청하지 않은 서두·마무리·평가·제안·파일을 제외하도록 정리했습니다. HTML의 Markdown 동반본은 요청했을 때만 생성합니다.
- 외부 URL은 제공 자료 또는 실제 도구 출력에서 가져옵니다. 없는 링크는 `링크 미확인 — 제공 파일 P01.md`처럼 표시합니다. 조회 스크립트 출력의 URL 사용법을 연결하고, URL 존재·논문 식별·주장 근거를 구분합니다.
- 출처 상세는 패키지 안의 reference에 모았습니다. HTML 템플릿에는 출처 카드, 기존/제안 흐름, 상태 배지의 주석 예시를 추가했습니다.
- episode/seed, 특정 세션 수, 세 개 질문에 묶인 예시를 분석 단위·자원 점유·요청한 질문 수에 대한 원칙으로 바꿨습니다. 스코어카드, proposal 완료 기준, taxonomy 문법은 유지했습니다.

분량은 YAML frontmatter를 뺀 SKILL.md 본문을 공백 기준으로 센 값입니다. 모델별 토큰 수나 효과 점수가 아닙니다.

| 스킬 | 수정 전 | 최종 |
|---|---:|---:|
| write-proposal | 796 | 565 |
| design-research | 667 | 503 |
| review-proposal | 758 | 577 |
| trace-research | 522 | 391 |

위 네 패키지는 reference를 포함한 전체 Markdown 분량도 줄었습니다. 파일 이동만으로 본문 수치를 줄인 것은 아닙니다.

## 실제 모델 실행

새 [합성 원자료](../tests/fixtures/scope-transfer.md)로 하천 관측·생산 lot·현미경 자원 배분 사례 6개를 추가했습니다. 기존 세 문장 proposal 및 스코어카드 사례를 포함해 단계별 8개를 확인했습니다. 기존 49개 전체를 재실행한 것은 아니며 저장소의 사례 정의는 총 55개입니다.

Claude Code 2.1.294의 실제 응답 모델은 `claude-sonnet-5-5`, `claude-opus-5-5`, effort `low`입니다. 각 사례는 새 임시 작업공간에서 스킬 사용 조건으로 한 번씩 실행했습니다. 모델에는 요청·원자료·해당 스킬을 주고 평가 기준은 숨겼습니다. Read·Glob·Grep·Write·Edit만 허용하고 외부 검색·셸·렌더링 도구는 제공하지 않았습니다. 별도 Codex `gpt-6-astra`, `low`가 요청·원자료·응답·실제 파일을 채점했습니다.

| 모델 | 단계 | 모든 기준을 통과한 사례 | 기준별 통과 / 실패 |
|---|---|---:|---:|
| Sonnet 5.5 | 첫 압축본 | 3/8 | 20 / 6 |
| Sonnet 5.5 | 공통 규칙 보완 후 | 6/8 | 23 / 3 |
| Opus 5.5 | 첫 압축본 | 3/8 | 19 / 7 |
| Opus 5.5 | 공통 규칙 보완 후 | 5/8 | 23 / 3 |

각 실행에는 기준 26개가 있으며 미평가는 0개입니다. 최초 실패와 재검사 출력·판정을 모두 보존했습니다. 단계 간 수치는 합산하지 않으며, 출력 변동이나 판정 오류를 추정할 반복 표본이 없어 개선의 인과 효과를 주장하지 않습니다.

최종 두 모델 모두 요청된 HTML 한 파일만 생성하기, 없는 URL을 만들지 않기, 확인한 인용 방향, 자원별 합산, 분석 단위 구분, 스코어카드 사례를 통과했습니다. 이 결과는 해당 입력에서 관측한 행동이며 일반적 보장은 아닙니다.

## 남은 실패와 판정의 한계

- 두 모델의 짧은 초록 요약은 제목·접근 범위와 미측정 결과를 구분했지만, 자료가 합성이라는 표시를 생략했습니다. 링크·DOI·arXiv ID를 날조한 실패는 아니었습니다.
- Sonnet은 질문 두 개 요청에 여러 하위 질문과 마무리 제안을 추가했습니다. 공통 규칙만으로 엄격한 범위 준수가 보장되지는 않습니다.
- Opus는 정확히 두 개의 의문문과 그 외 부가 문장 없이 응답했지만, 두 번째 문장이 고정 조건과 측정 대상을 함께 물어 자동 판정은 복합 질문으로 처리했습니다. 이를 독립 질문으로 셀지 하나의 비교 질문으로 볼지는 판단 여지가 있습니다. 자동 실패 기록은 그대로 유지했습니다.
- 최종 세 문장 사례는 두 모델 모두 문장 수를 맞췄습니다. Opus의 자동 실패는 첫 단어의 한자 혼입 오탈자를 한국어 출력 위반으로 처리한 결과입니다. 문장 수 실패와 구분합니다.
- Opus 요약 판정은 P01.md가 없다는 설명도 근거 부족으로 지적했지만, 실제 임시 작업공간에는 그 파일이 없고 원자료에 파일명이 언급되어 있습니다. 판정 모델은 실행 도구 기록 전체를 보지 못합니다. 합성 출처 표시 누락이라는 별도 실패는 남습니다.

일반 원칙을 더 늘려 특정 요청에 맞추기보다 이러한 실패를 공개합니다. 55개 전체 통과나 실제 사용 환경의 자동 스킬 선택, 장기 연구 효용은 이번 검사 범위에 포함하지 않습니다.

## 파일·화면·설치 확인

- 구조 검사와 단위 테스트 64개가 통과했습니다. 8개 패키지는 skill-creator 형식 검사와 Codex·Claude Code 임시 설치 후 파일 일치 검사도 통과했습니다.
- 템플릿 주석에서 부품을 조립한 합성 화면을 Chrome 1440px·390px에서 확인했습니다. 가로 넘침·깨진 내부 링크·외부 리소스 요청이 없었고, 출처/돌아가기 링크와 키보드 첫 이동을 확인했습니다.
- 인쇄용 PDF는 2쪽입니다. 텍스트 추출에서 접힌 상세 내용과 원문 주소의 포함을 확인했습니다. 이는 reader 검사이며 한 장 포스터 검사가 아닙니다.
- 최종 두 모델이 실제 생성한 HTML도 같은 화면 폭에서 넘침·내부 링크·자리표시자·외부 리소스를 검사하고 개요와 모바일 출처 카드를 시각적으로 확인했습니다. 포함된 유일한 외부 URL은 픽스처가 제공한 주소입니다. 합성 URL을 실제 논문 주소로 네트워크 검증하지 않았습니다.

  --run-dir eval-runs/scope-reproduction --conditions with_skill \
