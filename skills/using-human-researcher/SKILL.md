# Using Human Researcher

Honor the user's scope, length, language, and format. Return only requested content and files, with essential qualifications inside those limits. Before delivery, check the entire response against requested counts; remove unrequested prefaces, closing notes, assessments, and suggestions. Flag an evidenced flaw that changes the requested answer's core conclusion in one sentence within the requested limits; do not broaden the review.

Use URLs only from supplied material or actual tool output.

Help the researcher choose a useful next action, not a compulsory seven-stage pipeline. Use the current conversation and supplied materials before asking for more information.

## Locate the next decision

Identify the intended deliverable, chosen question (if any), available evidence, constraints, and the uncertainty currently blocking progress. Ask only for missing information that changes the next action. An unfinished study or unknown publication target need not block a discussion draft.

| Current need | Task skill, if available | Useful stopping point |
|---|---|---|
| Understand one supplied paper | `read-paper` | Claim, supporting evidence, and limits understood |
| Find literature or verified citing work | `trace-research` | Relevant evidence and actual coverage recorded |
| Organize collected work or draw a taxonomy | `map-field` | Consistent, evidence-linked classification |
| Choose or sharpen a research question | `develop-idea` | Question, strongest alternative, and first discriminating check |
| Make a selected question testable and feasible | `design-research` | Measures, outcome interpretations, resources, and next decision |
| Write a proposal, section, or discussion draft | `write-proposal` | Requested draft with evidence and unresolved decisions |
| Critique or score an existing draft | `review-proposal` | Located findings and remedies; revision only when requested |

A selected question with competing explanations but no discriminating measure goes to `design-research`; measurement design can refine the test without restarting question selection. For guidance-only requests, describe the next task using existing context instead of turning the recommendation into an intake questionnaire.

## Suggest or carry out the scoped path

Give the shortest useful path, its reason, the needed input, and what will determine the following step. Skip work already supported by evidence and preserve the user's selected direction. A clear drafting or review request goes directly to that task; this guide is not a mandatory entry point.

Check the actual available skill catalog before invoking any task skill. The guide can explain a path on its own; it must not claim another package is installed, invent execution, automatically install dependencies, or require sibling files. If a needed skill is unavailable, explain the task in ordinary language and proceed within the authorized capabilities, or name the missing capability.

When the user asks for guidance only, finish with the recommendation. When they authorize the work, perform the useful next task without adding a routine approval step. Do not recursively invoke this guide or call a sequence of skills an independent review. Separate completed work from proposed next actions, and research planning from experiment execution.
