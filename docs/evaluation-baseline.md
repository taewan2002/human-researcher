# 초기 지침의 스킬 유무 비교 기록

[검증 방법](evaluation.md) · [README](../README.md)

최종 배포 지침을 확정하기 전인 2026-10-08에 34개 합성 사례를 같은 모델로 스킬 사용·미사용 조건에서 실행했습니다. 이는 제공된 사례의 행동 회귀 점검이며, 실제 연구 품질이나 논문 채택 가능성의 측정이 아닙니다.

## 실험 조건

- 실행·판정 모델: `gpt-6-astra`, reasoning effort `low`, Codex CLI `0.153.4`.
- 각 사례·조건마다 새 프로세스와 작업공간을 사용했습니다. 실행 모델에는 판정 기준을 숨기고, 판정 모델에는 조건 이름과 스킬 지침을 숨겼습니다.
- 외부 검색 없이 같은 합성 입력과 로컬 파일·계산·렌더링 도구를 사용하도록 했습니다. 스킬 사용 조건에만 해당 스킬과 참조 자료를 추가했습니다.
- 판정은 별도 실행이지만 같은 모델 계열입니다. 출력의 문체나 형식에서 조건이 드러날 수 있습니다. 모델별 편향과 단일 실행의 변동성을 제거한 평가가 아닙니다.
- 전체 기준이 통과한 사례와, 위반이 확인된 기준, 필요한 증거가 없어 미평가인 기준을 구분했습니다. 렌더링을 보지 못한 시각 기준은 통과로 계산하지 않았습니다.

## 결과

초기 지침 스냅샷의 전체 비교 결과입니다. 현재 배포본의 전체 재실행 결과로 해석하지 않습니다. 이후 변경에 대한 검사는 [최종 검증 기록](evaluation-v0.1.0.md)에 따로 기록했습니다. 각 조건은 34개 사례, 139개 기준으로 판정했습니다.

| 조건 | 모든 기준 통과 사례 | 통과 기준 | 실패 기준 | 미평가 기준 |
|---|---:|---:|---:|---:|
| 스킬 미사용 | 27/34 | 128 | 9 | 2 |
| 스킬 사용 | 31/34 | 135 | 1 | 3 |

스킬 사용 조건의 실패 1건은 신규성 확인의 다음 단계를 빠뜨린 사례였습니다. 이를 수정한 추가 검증은 아래에 별도로 기록합니다. 미평가 3건은 taxonomy·포스터의 렌더링 관련 기준 2건과, 사용자 아이디어의 세부 내용이 없어 비교할 수 없었던 기준 1건입니다.

두 조건의 기준별 판정이 달라진 사례는 **6/34개**였습니다. 나머지도 회귀 검사로 유지하지만, 변별력 있는 별도 효과 평가를 대체하지는 않습니다. 이 수치는 **이 사례 집합의 판정 결과**입니다. 34개 사례는 난도나 연구 분야를 대표하도록 표집하지 않았으며, 판정 기준 수도 사례마다 다릅니다. 31/34를 일반적인 성공률로 해석하지 않습니다.

Description 라우팅은 **30/30**으로 기대 라벨과 일치했습니다. 일부 요청이 description의 표현과 유사해 일반화 근거로는 부족합니다. 실제 호스트의 자동 선택을 시험한 결과는 아닙니다.

## 관찰한 차이

### 초록만 보고 점수를 요청한 경우

같은 초록에 대해 Timely·Practical·Analytical·Implementable·Measurable로 평가해 달라고 요청했습니다. 초록은 구현과 평가를 미제공 본문 3·4절에 연결하고 있었습니다.

- **스킬 미사용:** 본문을 읽지 못했다고 설명하면서 Timely 8/20, Implementable 9/20, Measurable 7/20 등을 합쳐 **52/100점**을 제시했습니다.
- **스킬 사용:** 해당 세 항목을 **미평가**로 남기고 전체 총점을 보류했습니다. 제공된 문장으로 판단할 수 있는 Practical·Analytical만 근거 위치와 함께 평가했습니다.

차이는 높은 점수가 아니라 **불완전한 자료에서 어디까지 판단할 수 있는지**입니다. 이 사례의 판정은 프로젝트가 정한 결측 처리 기준에 따른 것으로, 모든 평가 상황에서 유일한 정답을 뜻하지는 않습니다.

### 동명이인의 논문을 연결하는 경우

픽스처에는 같은 이름의 저자와 서로 다른 소속·공란 소속만 있으며, 저자 식별자는 없습니다. 두 조건 모두 P02 → P01 인용은 맞게 찾았습니다.

- **스킬 미사용:** P03까지 P01 저자의 주제적 확장으로 묶었습니다. 인용 관계가 없다는 단서는 붙였지만 동일인이라는 전제는 남았습니다.
- **스킬 사용:** 논문 사이의 연구 연결과 개인의 확정된 이력을 구분했습니다. P03은 같은 저자라고 확인할 수 없다고 밝혔습니다.

## 줄인 지침과 유지한 지침

수정 전 비교에서는 짧은 요약, 검토만 요청한 범위 유지, 출처에 끼워 넣은 지시 무시, 오프라인 탐색 한계, 일반적인 비교 조건 점검 등을 두 조건 모두 통과했습니다. 해당 규칙을 완전히 지워도 된다는 증거는 아니므로, 핵심 원칙은 짧게 유지하고 중복 설명을 줄였습니다.

모든 스킬에 요청한 길이·형식을 우선하는 문장을 넣었습니다. 연구자 결정 보존·근거 구분·출처 속 지시 처리도 세 문장의 공통 원칙으로 압축했습니다. 반면 점수의 결측 처리와 근거 위치, proposal 완료 기준, taxonomy 관계 문법, 부정·모호한 결과의 해석은 구체적으로 유지했습니다.

| 스킬 | 수정 전 본문 단어 수 | 압축 후 본문 단어 수 |
|---|---:|---:|
| `design-research` | 691 | 426 |
| `develop-idea` | 497 | 317 |
| `map-field` | 456 | 332 |
| `read-paper` | 298 | 225 |
| `review-proposal` | 943 | 535 |
| `trace-research` | 469 | 392 |
| `write-proposal` | 814 | 565 |

본문 단어 수는 frontmatter를 제외하고 공백으로 나눈 값입니다. 참조 파일의 길이는 포함하지 않았으며, 길이 감소 자체를 성능 향상으로 보지 않습니다.

수정 전 스킬도 동명이인의 논문을 연구 궤적에 포함하는 오류를 냈습니다. 해당 실패를 보존하고, 같은 이름만으로 연구자 이력을 연결하지 않도록 지침을 명확히 한 뒤 다시 평가했습니다.

## 비교 과정에서 바로잡은 조건

초기 실행에는 스킬만 아는 다섯 기준 이름·20점 형식을 기대하는 부분이 있었습니다. 최종 비교에서는 초록 평가 요청에 다섯 기준 이름을 명시하고, 완전한 초안 평가에서는 선언한 척도의 일관성과 정확한 100점 환산을 보도록 수정했습니다. 저자 동일성에 관한 중복 기준도 하나로 합쳤습니다.

요청·자료·모델 설정이 같은 미사용 출력만 재사용했습니다. 기준이 바뀐 출력은 다시 판정했고, 요청이 달라진 초록 평가 사례는 다시 실행했습니다. 초기 실행의 집계를 최종 집계와 직접 비교해 개선 폭으로 제시하지 않습니다.

## 마지막 수정과 재검증

전체 비교에서 `no-false-first`는 최초 주장을 거부했지만, 추가로 어떤 정보를 확인할지 빠뜨렸습니다. `develop-idea`에 신규성이 미해결이면 필요한 아이디어 세부 내용이나 출처 확인을 구체적으로 제시하도록 한 문장을 보완했습니다.

변경된 스킬에 의존하는 5개 사례와 인접한 범위 유지 사례 3개를 새 스냅샷에서 추가 실행했습니다. 이 결과는 전체 비교의 첫 실패를 대체하지 않고 별도 기록으로 제공합니다.

추가 8개 사례·31개 기준 중 **30개 기준 통과, 실패 0개, 미평가 1개**였습니다. 모든 기준이 통과한 사례는 7/8개입니다. `no-false-first`의 다음 확인 단계는 통과했고, 세부 아이디어가 없어 차이를 확정할 수 없는 기준은 계속 미평가로 남겼습니다. 마지막 실행을 별도 전체 34개 재실행으로 표현하지 않습니다.

## 실행 기록과 리비전

공개 기록에는 실제 응답, 기준별 근거·판정, 모델·시각·사용량, 입력 픽스처, 스킬 파일 해시와 재사용 출처가 포함됩니다. 로컬 `eval-runs/`에는 실행 이벤트와 오류 출력도 보관합니다. 공개본에서는 운영 로그와 생성 도구의 컴파일 캐시를 제외했습니다.

[전체 기록 압축 파일](https://github.com/taewan2002/human-researcher/releases/download/v0.1.0/human-researcher-v0.1.0-evaluation.tar.gz)과 [SHA-256 체크섬](https://github.com/taewan2002/human-researcher/releases/download/v0.1.0/human-researcher-v0.1.0-evaluation.tar.gz.sha256)을 제공합니다. 압축 파일 내 `baseline/reports/`의 `original.json`, `release-candidate.json`, `novelty-fix.json`, `routing.json`, `source-check.json`에서 전체 원문과 판정을 확인할 수 있습니다. 각 실행의 스킬·픽스처 스냅샷과 생성 결과물도 포함합니다. 저장소에는 이 요약만 남겼습니다.

이 기록의 지침은 초기 비교 시점의 스냅샷입니다. 이후 길이 제약·섹션 트리거·arXiv 도구를 수정했으며, 현재 배포본과의 차이 및 추가 검사는 [최종 검증 기록](evaluation-v0.1.0.md)에 남겼습니다. 이 초기 비교 단계에서 추가 변경한 부분은 위 신규성 안내 문장과 OpenAlex 조회의 `truncated` 플래그 수정입니다. 후자는 알려진 총개수를 모두 받았는데 커서만 남은 응답을 부분 조회로 표시하지 않도록 고쳤으며 단위 테스트로 확인했습니다.

## 남은 한계

- 34개 사례는 개발 과정에서 만든 합성 사례이며, 지침 수정에도 사용했습니다. 보지 않은 실제 연구 과제에 대한 일반화 성능은 측정하지 않았습니다.
- 각 조건을 한 번씩 실행했습니다. 반복 실행에 따른 분산, 모델 간 차이, 연구자의 시간 절감이나 수정 부담은 측정하지 않았습니다.
- 판정 모델도 틀릴 수 있습니다. 공개 원문과 판정을 함께 읽어 주세요. 실제 발견과 미평가를 숨기지 않습니다.
- 텍스트 판정만으로 taxonomy·포스터의 렌더링 품질을 입증하지 못합니다. 파일 존재, 관계·내용 검사와 별개로 실제 화면 검토가 필요합니다.
- 라우팅은 description을 읽고 라벨을 고르는 1회 평가입니다. 실제 호스트의 자동 탐색과 실행 성공률은 아닙니다.
