# 아이디어 압축·핵심 결함 알림·리뷰 보고 검증

2026-10-09에 `develop-idea`를 504→399단어로 압축했습니다. 공백 기준 SKILL.md 본문 수치이며 YAML frontmatter는 제외합니다. 가장 강한 대안·구별 가능한 예측·추구 가치 판단은 유지하고 인과 관련 중복을 합쳤습니다.

## 반영한 수정

- 요청한 답의 핵심 결론을 바꾸는 **근거 있는 결함**은 요청한 분량 안의 한 문장으로 알립니다. 별도 리뷰나 추가 제안을 여는 예외가 아닙니다.
- 리뷰에서는 실제 수정·확인만 보고하고, 해결된 문제와 남은 핵심 결함을 구분합니다.
- 시각화에서는 글자 크기를 줄이기 전에 계층·그룹·여백을 활용하고, 실제 출력 크기에서 라벨과 인용의 가독성을 확인하도록 복원했습니다. 이번에는 템플릿 CSS나 공개 예제 이미지를 변경하지 않았습니다.
- `fetch_arxiv.py`가 자신의 디렉터리에서 모듈을 불러오도록 수정했습니다. `python -I`가 스크립트 디렉터리를 기본 import 경로에서 제외해 발생하던 오류를 재현한 뒤 고쳤습니다.

## 실행 범위와 결과

최종 지침으로 새 요약·수정 보고 사례 3개, 기존 아이디어·범위 사례 5개를 실행했습니다. 핵심 결함 알림의 반대 위험을 확인하려고 결함이 있는 요약과 정상 요약 2개에는 이전 공개 커밋 `68dec0b`의 지침도 같은 입력으로 실행했습니다. 이는 **이전 지침 대 새 지침** 비교이며 스킬 미사용 조건이 아닙니다.

Claude Code 2.1.294, `claude-sonnet-5-5`와 `claude-opus-5-5`, effort `low`를 사용했습니다. 각 사례는 새 임시 작업공간에서 한 번 실행했으며, 제공 자료·해당 스킬과 Read·Glob·Grep·Write·Edit만 사용했습니다. 실행 모델에는 기준을 숨기고, 별도 Codex `gpt-6-astra`, `low`가 응답과 실제 출력 파일을 채점했습니다.

| 모델 | 조건과 범위 | 모든 기준을 통과한 사례 | 기준별 통과 / 실패 |
|---|---|---:|---:|
| Sonnet 5.5 | 이전 지침 · 요약 2개 | 0/2 | 4 / 2 |
| Sonnet 5.5 | 최종 지침 · 변경 관련 8개 | 5/8 | 20 / 3 |
| Opus 5.5 | 이전 지침 · 요약 2개 | 1/2 | 4 / 2 |
| Opus 5.5 | 최종 지침 · 변경 관련 8개 | 6/8 | 21 / 2 |

최종 조건은 모델당 기준 23개, 이전 요약 조건은 6개이며 미평가는 없습니다. 서로 다른 범위의 수치를 직접 비교하거나 합산하지 않습니다. 재실행을 골라 성공률을 높이지 않았으며, 각 출력과 자동 판정을 보존했습니다.

두 모델의 최종 요약은 결론을 바꾸는 데이터 재사용 문제를 두 문장 안에서 지적했고, 정상적인 별도 평가 사례에는 그 결함을 잘못 붙이지 않았습니다. 이전 지침도 결함 자체는 지적했습니다. 이번 한 번의 비교는 좁은 예외가 출력을 불필요하게 늘리지 않은 사례를 보여줄 뿐, 효과나 무해성을 일반적으로 입증하지 않습니다.

두 모델 모두 실제 Conclusion 수정 파일을 전달하고, 문구를 고친 것과 독립 평가가 아직 필요하다는 점을 구분했습니다. 요청한 부분 외의 원문도 보존했습니다. 이는 평가 설계가 해결됐다는 뜻이 아닙니다.

## 남은 한계와 수동 확인

- Sonnet은 경쟁 설명을 구분하는 사례에서 관련 요인을 충분히 고정하지 못했고, 두 질문 요청에는 한 항목 안에 복수 질문을 묶었습니다.
- 합성 출처라는 표시와 발췌본 한정 맥락이 짧은 요약에서 생략됐습니다. 자동 판정은 같은 종류의 표시 누락을 일관되게 평가하지 않았습니다. Sonnet의 결함 요약은 출처 기준을 통과했지만 본문에 합성 자료임을 명시하지 않았습니다. 자동 통과 기록을 수정하지 않고 이 한계를 함께 공개합니다.
- Opus의 수정 보고는 요청이 한국어인데도 마지막 설명을 영어로 출력했습니다. 이번 수정 보고 기준에 언어가 포함되지 않아 자동 점수에는 잡히지 않았습니다.
- 사례별 한 번의 실행과 자동 채점은 모델 변동·실제 연구 품질·설치 환경의 자동 라우팅을 검증하지 못합니다. 기존 사례 전체를 재실행한 결과도 아닙니다. [앞선 범위 검사](evaluation-scope.md)의 실패와 별도로 읽어 주세요.

## 스크립트와 패키지

구조 검사, 8개 스킬 형식 검사, 단위 테스트 **66개**, Codex·Claude Code의 임시 설치 후 파일 일치 검사를 통과했습니다. 새 CLI 테스트는 외부 네트워크 없이 다음을 확인합니다.

1. 별도 임시 디렉터리에서 `python -I`로 `fetch_arxiv.py`와 `forward_citations.py`의 실제 CLI를 시작합니다. 현재 디렉터리와 PYTHONPATH에 동명 모듈이 있어도 패키지의 모듈을 사용합니다.
2. 잘못된 arXiv 입력은 import traceback 없이 오류 코드 2로 거부하며 출력 디렉터리를 만들지 않습니다.

이 검사는 isolated 실행 진입점과 오류 처리 검사입니다. 실제 arXiv 다운로드나 새 논문 검증을 이번에 실행했다는 뜻은 아닙니다.

## 원본과 재현

```sh
python3 scripts/evaluate.py --engine claude --model sonnet \
  --run-dir eval-runs/refinement-reproduction --conditions with_skill \
  --cases summary-conclusion-changing-flaw summary-no-manufactured-flaw \
  review-truthful-revision-report strong-counterargument adjustment-not-mechanism \
  bounded-question scope-analysis-unit scope-two-understanding-questions
```

`--model opus`로 다른 모델을 선택할 수 있습니다. 새 실행에는 기존 로그인과 계정 사용량이 필요하며 같은 결과를 보장하지 않습니다. 이전 지침 비교는 첨부 파일의 `*-prior/snapshot`에 고정되어 있습니다.
