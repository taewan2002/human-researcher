# Human Researcher 사용 가이드

[README](../README.md) · [English guide](guide.en.md) · [설치·업데이트](installation.md)

**지금 가진 자료와 원하는 결과를 알려 주세요.** 스킬 내부 단계를 관리하거나 일곱 개를 모두 순서대로 실행할 필요는 없습니다.

## 처음 쓰는 날

### 1. 설치하기

Codex나 Claude Code에게 다음 문구를 전달해 주세요.

```text
아래 설치 안내를 읽고 Human Researcher의 연구 스킬 7개와 사용 안내 스킬 1개를 설치해 주세요.
https://raw.githubusercontent.com/taewan2002/human-researcher/v0.1.0/docs/installation.md
```

기본은 현재 사용하시는 에이전트의 개인 설치입니다. 프로젝트에만 설치하려면 “이 프로젝트에만 설치해 주세요”를, 일부만 원하시면 스킬 이름을 덧붙여 주세요. 설치 확인 후 목록에 나타나지 않으면 새 대화를 시작하거나 에이전트를 다시 불러와 주세요. 자세한 경로·충돌 처리·업데이트 방법은 [설치 안내](installation.md)를 참고해 주세요.

### 2. 연구 맥락 전달하기

아래 항목 중 아는 것만 적어 주세요. 빈 항목을 그럴듯하게 채울 필요는 없습니다. PDF·논문 링크·직접 작성한 메모·기존 초안도 함께 제공할 수 있습니다. 도구가 읽을 수 없는 자료는 본문이나 발췌로 전달해 주세요.

```text
관심 분야 / 질문:
제가 이미 선택한 방향:
자료: [논문 링크, 첨부 PDF, 메모 또는 파일 경로]
자원: [장비, 데이터, 인원, 쓸 수 있는 시간]
목표 학회·연도·트랙 / 저널·논문 유형: [미정이어도 됨]
원하는 결과: [짧은 설명, 문헌 조사, proposal, 포스터 등]
작업 범위: [검토만 / 실제 수정, 외부 검색 가능 여부]
언어: 한국어
```

예를 들어 “한 사람이 주 10시간씩 4주 동안 진행할 계획이며 GPU 확보는 미정”처럼 작성하시면 됩니다. 자원 확보와 실행 시간을 확인한 사실로 오인하지 않도록 상태를 함께 적어 주세요.

### 3. 현재 상태에 맞춰 시작하기

| 지금 가진 것 | 시작할 스킬 | 첫 목표 |
|---|---|---|
| 읽고 싶은 논문 한 편 | `read-paper` | 무엇을 주장하고 어떤 근거가 있는지 이해 |
| 관심 분야만 있음 | `trace-research` 또는 `develop-idea` | 읽을 시작 문헌 또는 구체적인 질문 선택 |
| 여러 논문과 메모 | `map-field` | 접근법의 구조와 아이디어의 위치 확인 |
| 선택한 아이디어 | `design-research` 또는 `write-proposal` | 실행 가능한 방법·평가 계획으로 연결 |
| 이미 작성한 proposal | `review-proposal` | 핵심 결함과 다음 개선점 확인 |

### 다음 작업을 고르기 어려울 때

```text
using-human-researcher로 다음 작업을 골라 주세요.
이미 [논문 읽기·질문 선택 등]은 했고, 지금은 [막힌 판단]이 문제입니다.
현재 자료에서 필요한 다음 작업과 이유, 그 작업을 마쳤다고 볼 기준만 알려 주세요.
```

안내 스킬은 연구 스킬 7개와 별도로 제공됩니다. 이미 원하는 결과가 분명하다면 해당 스킬을 직접 쓰시면 됩니다. 안내만 요청하면 안내로 끝나며, 모든 스킬을 설치하거나 순서대로 실행하도록 요구하지 않습니다.

## 상황별로 복사해서 쓰기

### 논문을 탑다운으로 읽고 싶을 때

```text
read-paper로 이 논문을 탑다운으로 읽어 주세요.
문제 → 핵심 아이디어 → 중요한 근거 → 한계 순서로 설명하고,
제 관심 질문과 관련해서 깊이 읽을 절·그림·표를 알려 주세요.
논문이 실제로 보여준 것과 추가 해석을 구분해 주세요.
```

좋은 결과에는 핵심 주장과 확인 가능한 근거 위치가 있습니다. 초록만 제공했다면 본문·부록까지 읽은 것처럼 설명해서는 안 됩니다.

### 후속 연구와 Literature Survey가 필요할 때

```text
trace-research로 이 논문을 실제로 인용한 후속 연구부터 찾아 주세요.
관련 저자·연구실의 질문이 어떻게 발전했는지도 확인해 주세요.
기반 연구·최근 연구·가장 가까운 대안·반대 근거를 종합하고,
제 연구 질문과 baseline, 검증 계획에서 바뀔 부분을 설명해 주세요.
검색 날짜·범위와 확인하지 못한 자료도 남겨 주세요.
```

B가 A를 인용한다는 사실과 두 논문의 주제가 비슷하다는 판단은 다릅니다. 논문별 요약 뒤에는 **무엇이 합의됐고, 무엇이 다르며, 그래서 어떤 결정을 내려야 하는지**가 이어져야 합니다.

### 가지가 갈라지는 taxonomy가 필요할 때

```text
map-field로 이 문헌들을 계층형 taxonomy로 만들어 주세요.
큰 분야 → 접근법 → 세부 유형 → 대표 논문으로 가지가 갈라지게 해 주세요.
분기 기준과 분류 근거를 표시하고, 여러 계열에 속하는 방법과
정보가 부족한 문헌은 구별해 주세요. 제 아이디어의 위치도 보여 주세요.
편집 가능한 SVG와 분류 근거 메모를 저장해 주세요.
```

[계층형 taxonomy 예제](../examples/visual-taxonomy/README.md)를 함께 전달해 원하는 형태를 설명할 수 있습니다. 새 가지나 빈 칸을 발견했다는 사실만으로 신규성이 확정되지는 않습니다.

### 아이디어를 연구 질문으로 좁히고 싶을 때

```text
develop-idea로 이 아이디어를 구체적인 연구 질문과 가설로 정리해 주세요.
가장 가까운 선행연구와 실제 차이를 비교하고,
가장 강한 반론과 그 반론을 판별할 첫 검증을 제안해 주세요.
효과가 없더라도 무엇을 배울 수 있는지 포함해 주세요.
이미 선택한 [방향]은 유지해 주세요.
```

아직 방향이 없다면 마지막 문장을 “대안 몇 개를 비교하고, 이 제약에서 우선할 질문을 이유와 함께 추천해 주세요”로 바꿔 보세요.

### 연구의 견적과 스토리를 먼저 잡고 싶을 때

```text
write-proposal로 이 질문을 proposal 초안으로 발전시켜 주세요.
독자가 공감할 필요성, 기존 접근의 한계, 제안한 통찰과 필요한 근거를 연결해 주세요.
가장 위험한 가정과 처음 할 작은 판별 검증을 정하고,
[시간·인력·장비·데이터] 안에서 계속·축소·중단할 기준을 보여 주세요.
결과를 보기 전에 의미 있는 효과의 범위와 판단에 필요한 정밀도를 정해 주세요.
예상 결과와 실제 확인한 근거는 구분해 주세요.
```

좋은 계획은 그럴듯한 성공 이야기뿐 아니라 결과가 기대와 달라도 무엇을 배울지 설명합니다. 특정 점수가 올랐다는 사실이 더 넓은 능력 향상을 뒷받침하는지도 따로 확인해 주세요.

### 실험과 일정이 막막할 때

```text
design-research로 이 질문을 검증할 방법과 평가 계획을 구체화해 주세요.
필요한 입력·출력·구현, baseline·대조군, 측정 항목과 공정한 비교 조건,
긍정·부정·모호한 결과에서 내릴 판단을 연결해 주세요.
[자원과 시간] 안에서 먼저 할 최소 검증과 이후 확장 조건을 정해 주세요.
실험 실행은 하지 말고 계획만 작성해 주세요.
```

처리량을 모르면 일정은 조건부 추정입니다. 실행 시간, 사람의 작업 시간, 외부 대기를 구분하고 처음에 무엇을 재측정할지 확인해 주세요.

### 목표 학회·저널에 맞는 proposal이 필요할 때

```text
write-proposal로 이 자료를 연구 proposal로 완성해 주세요.
목표는 [학회·연도·트랙 또는 저널·논문 유형]입니다.
최신 공식 scope·심사 기준·관련 마감을 확인하고,
그 요구를 제 기여·선행연구·검증 계획·자원·일정에 연결해 주세요.
공식 요구사항과 전략적 추천을 구분해 주세요.
초안을 작성한 뒤 검토하고 현재 근거로 해결 가능한 결함은 수정해 주세요.
```

목표가 미정이면 해당 문장을 빼셔도 됩니다. 내부 proposal이 두 쪽이면 두 쪽으로 요청할 수 있습니다. 실제 제출 논문의 페이지 수를 내부 계획서에 그대로 적용할 필요는 없습니다.

### 지도교수·동료와의 미팅을 준비할 때

```text
write-proposal로 이 메모를 미팅용 1페이지 초안으로 정리해 주세요.
제 질문과 선택한 방향, 현재 근거, 가장 중요한 미해결 쟁점,
조언을 구할 질문을 담아 주세요. 답에 따라 무엇을 바꿀지도 설명해 주세요.
자료가 부족한 부분은 표시하고, 지금 논의할 수 있는 초안을 완성해 주세요.
```

이미 있는 초안의 점검만 필요하다면 “review-proposal로 미팅 전에 검토하고, 원문 수정 없이 핵심 쟁점과 질문을 정리해 주세요”라고 요청해 보세요. 논의할 준비가 됐다는 판단과 proposal의 핵심 결함이 해결됐다는 판단은 구분합니다.

미팅 후에는 실제로 받은 피드백과 본인이 선택한 변경을 전달해 주세요. “이 피드백을 반영하되, 조언과 확인된 근거를 구분하고 변경 이유를 남겨 주세요”라고 이어갈 수 있습니다. 스킬은 자료 작성을 도우며, 발송이나 일정 등록은 별도로 요청하신 경우에만 진행합니다.

### 이미 쓴 초안을 평가하거나 수정하고 싶을 때

검토만 원하신다면:

```text
review-proposal로 이 초안을 검토해 주세요. 원문은 수정하지 말아 주세요.
Timely·Practical·Analytical·Implementable·Measurable로 채점하고,
근거 위치·핵심 결함·가장 먼저 보완할 것을 알려 주세요.
[목표 학회·연도·트랙] 적합성은 점수와 따로 검토해 주세요.
```

실제 수정까지 원하신다면 이어서 요청해 주세요:

```text
지적한 핵심 결함 중 현재 자료로 해결 가능한 부분을 직접 수정해 주세요.
제가 선택한 방향과 원문 의미를 유지하고, 본문과 그림을 함께 고쳐 주세요.
변경 이유와 해결되지 않은 입력을 정리한 뒤 다시 확인해 주세요.
```

### 브라우저에서 읽고 근거를 따라가고 싶을 때

```text
write-proposal로 이 자료를 한국어 proposal로 완성해 주세요.
브라우저에서 바로 열 수 있는 HTML과 수정할 Markdown을 함께 주세요.
처음에는 왜 필요한 연구인지, 기존 방법에서 무엇을 바꾸는지,
무엇을 보면 판단할 수 있는지가 직관적으로 보였으면 좋겠습니다.
인용은 저자명만 쓰지 말고 논문 제목·원문 링크·참고한 이유를 붙여 주세요.
읽은 범위와 근거 위치를 표시하고, 가설과 결과를 구분해 주세요.
```

[전체 proposal HTML 예제](../examples/quantized-adaptation/proposal-reader.html)를 내려받아 브라우저에서 열면 서버 없이 읽을 수 있습니다. GitHub에서는 HTML 소스가 보이므로 파일을 저장한 뒤 열어 주세요. 목차와 본문의 논문 제목을 누르면 해당 내용과 출처 카드로 이동합니다. 출처 카드에는 원문 링크·읽은 범위·이 계획에서 사용하는 이유·근거의 한계가 있습니다. 원문을 여는 데에는 인터넷 연결이 필요합니다.

전체 계획은 화면에 맞춰 읽고, 세부 통제는 펼쳐서 확인하며, 인쇄할 때는 접힌 내용도 포함합니다. 한 장 포스터와 달리 전체 문서를 인쇄하면 여러 쪽이 될 수 있습니다. HTML만 원하시면 그렇게 지정해 주세요. Markdown만 필요한 요청에는 HTML을 추가하지 않습니다.

### 한 장 포스터로 설명하고 싶을 때

```text
write-proposal로 이 계획을 한국어 한 장 포스터로 만들어 주세요.
문제·문헌 근거·핵심 질문·방법·검증·결과별 판단이 연결되게 해 주세요.
제안한 방법과 이미 확인된 사실을 시각적으로 구별해 주세요.
편집 가능한 HTML/SVG를 저장하고, 도구가 가능하면 PDF로 내보내
실제 한 페이지인지와 글자·연결선·출처 링크가 잘 보이는지 확인해 주세요.
```

[포스터 예제](../examples/quantized-adaptation/poster.pdf) · [편집 가능한 HTML](../examples/quantized-adaptation/poster.html). 단순 비교를 원하면 “그림 없이 표 하나로”처럼 범위를 줄여도 됩니다.

## 실제 예제로 따라가기

[LoRA·QLoRA 예제](../examples/quantized-adaptation/README.md)는 공개 논문에서 “어떻게 메모리를 줄일 수 있을까요?”를 **고정한 모델·데이터 조건에서 입력 길이에 따른 양자화의 메모리 이점을 어떻게 확인할 수 있을까요?**로 좁히는 과정을 보여줍니다.

1. [출처 메모](../examples/quantized-adaptation/sources.md)에서 확인된 인용 관계와 읽은 범위를 살펴보세요.
2. [Proposal](../examples/quantized-adaptation/proposal.md)에서 비교 조건·측정·자원 제약을 확인해 보세요.
3. [검토 기록](../examples/quantized-adaptation/review.md)에서 어떤 주장과 설계를 보완했는지 비교해 보세요.
4. [한 장 포스터](../examples/quantized-adaptation/poster.pdf)가 같은 질문과 가정을 유지하는지 확인해 보세요.

처음부터 예제의 완성본을 정답으로 주기보다, 시작 요청과 원문 논문·본인의 제약으로 실행한 후 비교하시면 결과를 판단하기 좋습니다. 이 예제는 실행한 실험이나 신규성 입증 사례는 아닙니다.

## 평가표 읽기

| 점수 | 의미 |
|---|---|
| 0 | 제공된 범위 안에서 핵심 연결이 빠졌거나, 이를 무너뜨리는 모순이 확인됨 |
| 1 | 주장은 있으나 중요한 설명이나 설계가 거의 정해지지 않음 |
| 2 | 구체적인 경로는 있으나 판단을 바꿀 중요한 빈틈이 남음 |
| 3 | 근거와 설계가 연결되고, 남은 가정에 현실적인 확인 계획이 있음 |
| 4 | 강한 반론·제약까지 다루며 적용 한계와 대안이 명확함 |
| 미평가 | 제공 자료나 접근 범위가 부족해 판단할 수 없음 |

다섯 항목이 모두 평가되면 20점 만점으로 합산하고, 필요하면 5를 곱해 100점으로 환산합니다. 하나라도 미평가면 전체 총점은 보류합니다. **검증 계획이 없는 것과, 계획한 실험을 아직 하지 않은 것은 다릅니다.** 점수는 개선을 돕는 판단이며 채택 확률이나 성과 예측치는 아닙니다.

문서를 잘 썼다는 이유로 연구자가 직접 설명·구현할 수 있다고 결론 내리지 않습니다. 본인 이해도를 확인하고 싶다면 “가장 가까운 대안이 왜 부족한지, 어떤 결과에서 가설을 버릴지 제가 설명해볼 테니 검토해 주세요”라고 이어갈 수 있습니다.

## 결과가 기대와 다를 때

| 상황 | 이렇게 이어서 요청하기 |
|---|---|
| 요약이 길고 중요한 점이 안 보임 | “제 질문에 영향을 주는 주장 세 개와 근거 위치만 남겨 주세요.” |
| 관련 논문은 많은데 방향이 안 잡힘 | “가장 가까운 대안과 반대 근거 중심으로 정리하고, 제가 결정할 질문을 좁혀 주세요.” |
| 표만 나오고 taxonomy가 아님 | “분기 기준이 보이는 계층형 트리로 만들어 주세요. 이 예제 형태를 참고해 주세요.” |
| 방법은 있는데 무엇을 측정할지 모름 | “핵심 가설과 가장 강한 대안을 구별할 대조군·측정·판정 기준을 연결해 주세요.” |
| 근거가 없는 내용을 단정함 | “확인한 출처 위치를 보여주고, 찾지 못한 내용은 미확인으로 바꿔 주세요.” |
| 수정했는데 그림은 예전 상태임 | “본문·taxonomy·포스터의 주장과 용어가 일치하도록 함께 갱신해 주세요.” |

기록을 남기고 싶다면 “원문은 보존하고 조사 메모·proposal·검토·그림을 파일로 저장해 주세요”라고 요청해 주세요. 폴더 구조는 현재 프로젝트를 따르며, 대화만으로 작업할 때 새 파일을 만들 필요는 없습니다.

스킬은 사용하시는 에이전트의 모델·검색·파일·렌더링 도구로 동작합니다. 접근할 수 없는 원문이나 사용할 수 없는 내보내기 도구가 있다면, 확인된 부분과 남은 작업을 구분해 안내합니다. [기여 안내](../CONTRIBUTING.md)에는 재현 가능한 실패를 공유하는 방법이 정리되어 있습니다.

## arXiv 논문 가져오기

설치 후 평소처럼 논문 링크와 필요한 작업을 알려 주세요.

```text
trace-research로 https://arxiv.org/abs/2106.09685v1 논문을 가져와 주세요.
버전과 제목을 확인하고, 가능한 HTML 본문이나 PDF를 저장해 주세요.
이 논문을 인용한 2023년 양자화 관련 후속 연구도 찾아 주세요.
검색 후보와 원문에서 인용을 확인한 논문을 구분해 주세요.
```

에이전트는 패키지의 조회 도구로 arXiv 메타데이터를 확인하고, HTML이 없으면 PDF를 시도할 수 있습니다. 초록만 확보한 상태와 본문 확보 상태를 구분하며, PDF 텍스트를 추출해도 표·수식·그림의 시각 검토가 끝난 것은 아닙니다. 특정 버전이 중요하면 `v1`처럼 버전을 지정해 주세요. 기존 파일과 내용이 다르면 덮어쓰지 않습니다.

[옵션·실패 상태·의존성 안내](../skills/trace-research/references/retrieval.md)에서 직접 실행 명령도 확인할 수 있습니다.
