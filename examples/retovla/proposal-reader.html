01

연구의 필요성과 선행연구

왜 이 문제를 풀어야 하나요?

관계에 맞는 대상을 고르는 일은 조작 성공의 출발점입니다. 예를 들어 같은 모양의 컵 두 개 중 “접시 뒤에 있는 컵”을 집어야 한다면, 컵이라는 물체 종류를 알아보는 것만으로는 충분하지 않습니다. 잘못된 컵을 안정적으로 집어도 과제는 실패합니다. 이 장면은 문제를 설명하는 예시이며, 특정 모델에서 관측한 실패 사례는 아닙니다. 본 연구는 이런 관계에 따른 대상 선택을 제한된 계산 자원에서 개선하는 문제에 집중합니다.

경량 VLA는 이 문제를 실험할 현실적인 출발점입니다. TinyVLA는 작은 VLM과 diffusion action decoder를, SmolVLA는 경량 VLM과 flow-matching Action Expert를 제시합니다. 두 연구가 보여주는 방향은 “큰 모델을 쓸 수 있어야 로봇 연구를 할 수 있다”는 제약을 줄이는 것입니다. 따라서 다음 질문은 모델을 무조건 키우는 것이 아니라, 이미 사용하는 모델과 입력을 유지하면서 행동의 품질을 더 높일 수 있는가입니다. 작은 모델이 반드시 공간 관계를 처리하지 못한다는 전제는 두지 않습니다.

본 제안의 실용적 가치는 같은 하드웨어·데이터 예산에서 유용한 개선을 얻을 때 생깁니다. 추가 경로의 연산·메모리 증가까지 측정하고, 그 비용을 감수할 만큼 대상 선택과 조작 성공이 좋아지는지 판단합니다. 효과가 없다면 어느 조건에서 단순한 기존 경로로 충분한지를 밝히는 결과도 설계 결정에 도움이 됩니다.

VLA 분야의 taxonomy

분류 질문은 “VLM의 표현에서 로봇 행동을 어떤 형태로 출력하나요?”입니다. 이산 행동 토큰을 예측하는 계열과 연속 행동을 생성하는 계열로 나누고, 각 계열에서 실제 출력 연산을 세분화했습니다. VLM 기반 조작 정책 8편과 이 제안의 위치를 나타내며, 모든 VLA를 망라하는 공식 분류는 아닙니다.

RetoVLA의 위치: 연속 행동 생성 → flow matching 계열이며, 직접 비교할 이웃은 SmolVLA입니다. 새 행동 생성 계열을 제안하는 것이 아니라 시각 특징을 기존 Action Expert에 전달하는 경로를 바꿉니다. 공간 정보 주입·경량화·요약 토큰은 이 트리를 가로지르는 별도 설계 축입니다.

OpenVLA와 OpenVLA-OFT는 모델 계보가 이어져도 출력 방식이 달라 서로 다른 가지에 놓입니다. 이 그림의 diffusion과 flow matching은 논문이 채택한 학습 목표·생성 절차를 구분한 것이며, 두 계열이 이론적으로 무관하다는 뜻은 아닙니다. 선은 범주 소속, 점선 테두리는 아직 검증할 제안 방법을 뜻합니다.

선행연구는 어디까지 왔나요?

① 경량화는 이미 가능한 방향입니다. SmolVLA와 TinyVLA는 효율적인 backbone과 연속 행동 생성의 조합을 제시합니다. 여기서 이어받을 질문은 경량화 자체가 아니라 특징을 행동 모듈에 전달하는 방식입니다. 논문별 보고 성공률은 데이터·로봇·학습 조건이 달라 하나의 순위로 합치지 않습니다.

② 공간 정보를 명시적으로 넣는 접근도 있습니다. SpatialVLA: Exploring Spatial Representations for Visual-Language-Action Models는 추정 depth와 카메라 내부 파라미터로 만든 Ego3D encoding, 그리고 Adaptive Action Grids를 사용합니다(§III-A). 본 연구는 depth 경로·행동 표현을 추가로 바꾸지 않고 기존 RGB 특징의 집계와 전달을 먼저 검토합니다. 이는 변경 범위의 차이이며 SpatialVLA보다 싸거나 우수하다는 비교 결과가 아닙니다.

③ 학습 가능한 토큰으로 시각 정보를 모으는 원리는 이미 알려져 있습니다. Flamingo의 Perceiver Resampler와 BLIP-2의 Q-Former는 learned queries로 시각 특징을 모아 언어 모델에 전달합니다. CogACT도 VLM의 cognition token 표현으로 diffusion action module을 조건화합니다. 로봇 정책인 Octo: An Open-Source Generalist Robot Policy도 readout tokens의 표현을 diffusion action head에 연결합니다. 따라서 “소수의 학습 가능한 토큰으로 요약해 행동에 사용한다”는 설명만으로 새로운 기여가 되지는 않습니다.

④ Register라는 이름과 실제 연산을 구분해야 합니다. Vision Transformers Need Registers는 ViT 입력에 내부 계산용 토큰을 추가합니다. 이 제안의 register queries는 고정 encoder가 만든 특징 뒤에서 집계하므로, 연산상 visual resampler 계열과도 가깝습니다. Register 연구는 설계의 동기를 주지만, 이 토큰이 자동으로 3D 구조를 표현한다거나 행동 성능을 높인다는 증거는 아닙니다.

이 연구가 답하려는 공백

위 문헌을 연결해 도출한 검증 질문은 다음과 같습니다. “고정한 경량 VLM과 기존 행동 경로를 유지할 때, 이미지 특징을 소수의 query로 모아 Action Expert에 직접 추가 전달하는 것이 같은 예산의 단순 요약보다 도움이 되는가?” 앞의 연구가 이 제안과 같은 조건의 효과·비용 비교를 대신해 주지는 않습니다. 다만 이 문헌 범위만으로 누구도 같은 구성을 시험하지 않았다고 단정할 수는 없습니다.

가능성을 기대하는 이유는 새로운 시각 encoder를 학습하지 않고도 기존 특징에서 행동 학습에 유용한 요약을 선택하도록 최적화할 수 있기 때문입니다. 가장 강한 반론은 기존 Action Expert의 cross-attention이 이미 그 선택을 충분히 하고 있을 수 있다는 점입니다. Query가 필요한 정보까지 압축하거나 기존 정보를 중복 전달할 수도 있습니다. 따라서 baseline A뿐 아니라 같은 위치·토큰 수의 pooling B를 함께 두어, 추가 경로와 학습 가능한 집계의 가치를 구분합니다.

이 단계에서 제안할 기여는 기존 경량 VLA에 작은 요약 경로를 붙이는 설계와 그 적용 조건·효과·비용의 검증입니다. 새로운 query 원리, 최적의 주입 위치, 다른 VLA 전체에 대한 우위까지 확장하려면 별도의 비교 근거가 필요합니다.

필요성을 첫 실험에서 어떻게 확인하나요?

현재 proposal에는 기준선의 관계별 오류를 직접 관측한 자료가 없습니다. 첫 pilot에서 같은 물체·배경을 유지하고 관계 또는 지시만 바꾼 개발 장면을 사용해 대상 선택 오류, 올바른 대상에 대한 조작 오류, 지시 변화에 대한 반응을 나누어 기록합니다. 정답 대상과 판정 규칙은 실행 전에 고정합니다. 이 분류는 행동 수준의 진단이며 내부 표현이 원인이라는 증명은 아닙니다.

관계 변화에 따른 반복 오류가 있고 요약 경로가 이를 줄인다면 후속 확인 실험의 이유가 강해집니다. 반대로 기준선이 이미 관계에 잘 반응하고 실패가 주로 접촉·제어에서 생긴다면, 공간 관계를 중심으로 한 필요성은 약해집니다. 그 경우 확인 실험 전에 질문을 다시 좁히거나 중단합니다. “필요할 것 같다”를 곧바로 대규모 실행으로 이어가지 않는 결정 기준입니다.

문헌 범위: RetoVLA 연구 시작 관점을 위한 예제로, 2025-09-24 이전 공개 버전 13편을 선정해 2026-10-09에 확인했습니다. 분야 전체의 체계적 조사나 현재 최신 성능 순위는 아닙니다. 검색어·읽은 위치·접근 제한은 출처 기록에 남겼습니다.

02

연구 질문과 가설

주 질문: 같은 경량 VLA·데이터·학습량에서 register 기반 장면 요약을 Action Expert에 제공하면, 제한된 추가 비용으로 조작 성공률을 개선할 수 있을까요?

  • H1 — 유용성: Register 요약 조건 C는 요약 경로가 없는 기준선 A보다 조작 성공률이 높을 것입니다.
  • H2 — 정보의 선택: C는 같은 토큰 수와 유사한 모듈 규모의 pooling 요약 B보다 관계 변화에 따른 대상 선택을 잘할 것입니다. C와 B가 비슷하면 학습 가능한 register query의 필요성은 약해집니다.
  • H3 — 효율성: C의 추가 latency와 peak memory는 정한 비용 한도 안에 있을 것입니다. 성공률이 높아도 한도를 넘으면 효율적인 개선이라는 주장을 수정합니다.

여기서 register 요약은 설계 후보의 이름입니다. H1·H2가 지지되어도 기존 resampler보다 새로운 원리라는 뜻은 아닙니다. 성공률은 행동의 유용성 지표입니다. 이것만으로 특정 3D 표현이나 일반적인 공간 추론 능력을 입증하지 않습니다.

03

제안 방법

현재 RGB 관측, 언어 지시, 로봇 상태를 입력하고 action chunk를 출력합니다. 평가 시 미래 영상·정답 행동을 입력하지 않습니다. 시연의 action chunk는 학습 target으로만 사용합니다.

  1. SmolVLA 계열의 사전학습 VLM에서 이미지 patch 특징 P와 기존 행동 조건 특징을 얻습니다.
  2. 학습 가능한 register queries Qreg로 장면 요약 R = Attention(Qreg, P, P)를 만듭니다. 첫 후보는 K=2개입니다.
  3. R을 Action Expert 차원으로 투영하고, 학습 가능한 scalar gate를 거친 K/V를 기존 K/V 뒤에 연결합니다. 첫 후보는 마지막 cross-attention 층에만 주입합니다.
  4. 기존 flow-matching action loss로 Action Expert와 새 요약·projection·gate를 학습합니다. VLM은 고정합니다.

기존 SmolVLA checkpoint에 그대로 꺼내 쓸 register 출력이 있다고 가정하지 않습니다. 여기서는 기존 시각 표현을 새로운 작은 query 모듈로 집계합니다. ViT 입력에 register를 추가하는 S2와 삽입 위치·학습 목적이 다릅니다. 새 모듈의 parameter와 연산 비용을 실측하며 “비용 0”을 전제로 하지 않습니다.

고정할 학습 조건과 recipe

S1의 공개 recipe를 출발점으로 같은 시작 checkpoint, VLM 깊이, 전처리, 데이터 split, optimizer, 학습률 schedule, action horizon, flow step, 정규화와 checkpoint 선택 규칙을 사용합니다. 기준 설정은 100k updates, effective batch 64, 고정 VLM, 10 flow steps로 제안합니다. 메모리 때문에 microbatch를 줄이면 모든 조건의 effective batch와 update 수를 유지합니다. 공통 모듈은 대응하는 초기화와 데이터 순서를 사용하고, 새 모듈 seed도 기록합니다.

04

공정한 비교와 평가

조건 바꾸는 것 비교의 목적
A · Baseline 별도 요약 경로 없음 원래 경량 정책의 기준 성능·비용
B · Pooling control 평균 pooling 후 projection으로 K=2개 요약 토큰을 생성해 같은 위치에 주입 단순 요약 경로만으로도 충분한지 확인
C · RetoVLA 학습 가능한 K=2개 register query로 요약해 같은 위치에 주입 학습 가능한 집계가 주는 차이 확인

B와 C는 같은 출력 토큰 수·주입 위치·gate 형식을 유지합니다. B의 projection 폭은 parameter 예산을 가깝게 맞추도록 성능을 보기 전에 정합니다. 정확히 같은 연산·용량이라고 간주하지 않고 차이를 함께 보고합니다.

가까운 선행방법과 비교하는 범위: A/B/C는 이 backbone에서 추가 경로와 학습 가능한 집계가 필요한지를 검증하는 최소 비교입니다. C 자체도 작은 learned-query resampler의 한 형태이므로, 이를 별도의 이름으로 한 번 더 구현해 독립 기준선처럼 세지 않습니다. “기존 resampler보다 낫다”를 주장하려면 Flamingo형 latent-to-latent attention 등 실제 연산이 다른 후보를 같은 토큰·parameter 예산에 맞춰 추가 비교해야 합니다. “마지막 층이 더 낫다”에는 같은 요약을 다른 층에 넣는 비교가 필요합니다. 이 확장 비교는 아래 9회 학습에 포함되지 않으며, 현재 기여를 그 주장까지 넓히지 않습니다.

TinyVLA·SpatialVLA·Octo는 설계와 문제 설정을 설명하는 선행연구입니다. 원 논문의 서로 다른 benchmark 성공률을 A/B/C 표에 섞어 넣지 않으며, 모델 간 우위를 논하려면 같은 데이터·관측·평가와 별도 예산으로 비교해야 합니다.

최소 연구 범위와 확장

첫 확인 실험은 LIBERO-Spatial 10개 task, 3조건 × 3 training seeds = 9회 학습으로 제안합니다. 각 task의 개발 상태와 분리한 50개 확인용 초기 상태를 모든 조건·seed에 동일하게 적용하면 4,500 episodes입니다. 동일 상태의 반복을 새로운 독립 task로 세지 않습니다. 상태 수·생성 방법·hash를 고정하고, 학습·개발과 분리할 수 없다면 확인 실험이라는 주장을 보류합니다.

Pilot는 별도 개발 상태에서 실행합니다. 시작 checkpoint의 사전학습 데이터와 평가 task의 중복 여부를 확인하며, 중복이 있거나 미확인이면 새로운 task의 일반화로 표현하지 않습니다. 최종 checkpoint를 평가하고 결과를 본 뒤 유리한 seed·task만 고르지 않습니다. 실패·timeout·사전 정의한 무효 episode 기준과 제외 사유를 남깁니다.

Spatial 비교가 해석 가능하고 예산이 확보되면 Object·Goal·Long과 실물로 확장합니다. 이 확장은 위 9회 학습·4,500 episodes 및 아래 예산에 포함하지 않습니다.

지표와 구성 타당도

개념 측정 방법 피해야 할 해석
조작 유용성 Task별 성공률과 task 동일 가중 평균, seed별 결과, C−A·C−B 차이와 불확실성 평균만으로 모든 task에서 유용하다고 주장
관계에 따른 행동 물체 종류를 유지하고 배치·관계 지시를 바꾼 대조쌍에서 올바른 대상 선택과 최종 성공을 각각 측정 하나의 benchmark 점수를 일반 공간 능력과 동일시
배포 비용 같은 장비·해상도·batch·flow steps의 end-to-end policy latency, peak GPU memory, parameter 수 Parameter 수만으로 실행 속도를 대신 설명

관계 대조쌍은 초기 계획상 6개 장면쌍 × 5개 초기화 × 2개 장면 × 3조건 × 3seeds = 540 episodes로 제안합니다. 개발용 장면으로 집계 규칙을 정한 뒤 확인용 배치와 지시를 별도로 고정합니다. 장면쌍별 원시 결과를 보존하고 유효한 쌍을 확보할 수 없다면 공간 관계 주장을 보류합니다. 이 분석은 별도 진단이며 주 성공률에 합산하지 않습니다.

Task·seed·초기 상태의 구조를 보존해 차이와 95% 구간을 추정하고 seed별 결과를 함께 제시합니다. 구체적인 재표집 절차와 반복 수는 pilot 후 고정합니다. Training seed 3개는 불확실성 추정에 제한적이며, episode 수가 많다는 이유로 모델 간 변동을 무시하지 않습니다.

결과를 보기 전에 정할 판단

계획을 구체화하기 위한 제안 기준은 실용적 성공률 차이 δ=5%p, baseline 대비 latency +15% 이내·peak memory +10% 이내입니다. 측정값이나 논문에서 검증된 기준이 아닙니다. 로봇의 요구 응답 시간과 pilot 변동으로 타당성을 검토한 뒤 확인 실험 전에 고정합니다.

관측 결론과 다음 행동
C−A 차이 구간의 하한이 +δ 이상이며 비용 기준 충족 해당 조건에서 의미 있는 행동 개선을 지지합니다. H2는 C−B와 관계 대조쌍을 별도로 확인합니다
성공률 개선은 있으나 C와 B의 차이를 구별하지 못함 요약 경로의 유용성과 register 특유의 이점을 분리합니다. “둘이 같다”로 단정하지 않습니다
정밀하게 추정한 차이 구간 전체가 [−δ,+δ] 안에 있음 해당 조건에서 실용적으로 작은 효과라는 근거로 해석합니다
구간이 의미 있는 이득·손해 양쪽에 걸침 판단에 필요한 정밀도가 부족합니다. 정한 예산으로 개선할 수 없으면 결론을 보류합니다
특정 task 악화 또는 비용 한도 초과 적용 범위를 줄이거나 구조를 단순화합니다. 유리한 평균으로 손해를 숨기지 않습니다

평가 시 토큰 교란·제거는 보조 분석으로만 사용합니다. 분포 밖 입력에서의 성능 저하만으로 공간 의미나 개선의 전체 원인이 증명되지는 않습니다.

05

연구의 견적과 마일스톤

계획 환경: NVIDIA GeForce RTX 5090 GPU 1개를 기준으로 학습과 평가를 진행합니다. 공개 데이터·시뮬레이터와 기존 VLA 구현을 사용하며, 해당 장비에서의 메모리 사용량·처리량과 GPU 사용 가능 시간을 pilot에서 확인합니다. 기간은 이 조건이 충족될 때의 simulation 중심 5–7주이며, 실측 견적에 따라 조정합니다.

단계 기간 가정 줄일 불확실성과 완료 기준
선행연구·기준선 준비 1주 가까운 구현과의 차이, 데이터 권리·중복, 시작 checkpoint·입력·평가 경로 확인; 개발 장면의 대상 선택·조작 오류를 분리
요약 모듈·pilot 1주 Shape·gradient·비활성 경로 검사, 실제 메모리·처리량·변동 확인; 전체 실행 가능 여부 결정
고정한 확인 비교 2–3주 A/B/C의 학습·4,500 episodes·관계 진단 540 episodes를 종료; 실패 포함 기록 수집
해석·초안·공개 자료 정리 1–2주 주장과 한계, 비교 도식, 결과표, 재현 설정을 연결

장비 시간 계산 예시: RTX 5090 1개에서 학습이 초당 2 updates라면 9 × 100,000 ÷ 2 ÷ 3,600 = 125 GPU-hours입니다. Episode가 평균 2분이고 GPU 하나를 점유한다면 (4,500 + 540) × 2 ÷ 60 = 168 GPU-hours입니다. 합계 293시간에 20% 여유를 두면 약 352 GPU-hours입니다. 이는 처리량을 가정한 산식이며 RTX 5090에서 측정한 견적이 아닙니다. Pilot와 관계 장면 제작에 드는 시간은 별도입니다. 장비 대기·실패 재실행·사람의 구현 시간을 GPU 시간과 섞지 않습니다.

예시 계획 상한은 pilot 24 GPU-hours, 확인 비교 360 GPU-hours로 두고 실측 후 재검토합니다. 예상치가 상한을 넘으면 확인 결과를 보기 전에 범위와 예산을 다시 정합니다. 정밀도를 확보할 수 없는 축소라면 탐색 연구로 한정합니다. 이 수치는 제안서의 계획안이며 실행 승인이 아닙니다.

가장 먼저 확인할 것

  1. 시작 checkpoint·데이터의 이용 조건과 pretraining 범위를 확인합니다.
  2. 기준선의 관측·정규화·action 실행·성공 판정을 검사하고, 개발 장면에서 관계에 따른 대상 선택 오류와 조작 오류를 구분합니다.
  3. RTX 5090 1개에서 A/B/C 한 batch의 gradient·메모리와 짧은 pilot의 처리량을 측정합니다.
  4. 비용·δ·정밀도·재표집 절차와 확인용 상태를 고정하고 진행 여부를 결정합니다.

실물 연구에는 로봇·카메라·시연·공간·운영자·안전 절차가 추가로 필요합니다. 해당 접근과 자원이 확인되기 전에는 실물 일정·성공률을 약속하지 않습니다. 개인정보가 있는 영상은 수집·공개 동의와 이용 권리를 먼저 확인합니다.

기대 기여와 논문의 스토리

독자: 제한된 계산 자원으로 시각·언어 기반 로봇 조작을 구현하는 연구자입니다. 목표 학회·연도·트랙은 아직 정하지 않았으며 제출 규정 적합성은 별도 확인합니다.

이야기의 출발은 **“제한된 자원에서도 관계에 맞는 대상을 골라 조작해야 한다”**입니다. 경량 정책과 query 기반 정보 집계라는 선행연구를 연결해, 기존 시각 정보를 행동에 전달하는 작은 보조 경로를 제안합니다. 필요성은 기준선의 오류 진단으로, 유용성은 공정한 A/B/C 비교로, 실용성은 실제 비용으로 확인합니다. 이 근거들이 뒷받침하는 범위 안에서 어떤 조건에서 왜 이 설계를 선택할 만한지 설명합니다.

확보한 근거 쓸 수 있는 기여
기준선·단순 요약 대비 반복되는 이득과 비용 충족 Register 기반 행동 조건화 방법과 조건별 효과·비용
행동 이득은 있으나 공간 관계 해석은 지지되지 않음 행동 개선으로 주장을 좁히고 공간 추론 기여는 보류
단순 요약과의 차이가 정밀하게 작음 더 단순한 요약 경로와 그 적용 조건에 대한 분석

최초성·일반적인 3D 이해·실물 적용성은 각각의 근거가 있을 때만 주장합니다. 다음 논의의 핵심은 이 질문의 가치, 5%p·비용 기준의 실용성, 가용 자원으로 확보할 수 있는 정밀도입니다.
