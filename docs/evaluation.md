# 검증 방법과 확인한 범위

[사용 가이드](guide.md) · [아이디어·리뷰·isolated 실행 검증](evaluation-refinement.md) · [요청 범위·출처 검증](evaluation-scope.md) · [v0.1.0 검증 기록](evaluation-v0.1.0.md) · [초기 지침 비교 기록](evaluation-baseline.md)

Human Researcher는 **패키지가 설치되는지**, **지침이 모델 행동에 영향을 주는지**, **실제 연구에 도움이 되는지**를 구분해서 확인합니다. 구조 검사 통과나 에이전트의 점수만으로 연구 효과를 주장하지 않습니다.

## 패키지와 도구 검증

`scripts/validate_repo.py`는 8개 패키지의 메타데이터와 버전, 독립적인 참조 범위, Markdown·HTML 링크와 앵커, 패키지 밖으로 나가는 심볼릭 링크, 행동·라우팅 사례의 구조를 검사합니다. 단위 테스트는 잘못된 입력을 거부하는지와 조회·설치 도구의 실제 동작을 확인합니다.

`scripts/smoke_install.py`는 Skills CLI 1.7.1로 임시 Codex·Claude Code 프로젝트에 설치한 파일을 원본과 비교합니다. 공개 태그 URL도 같은 방식으로 검사할 수 있습니다. 설치 기록 도구는 저장소·태그·커밋·파일 해시를 남기며, 업데이트 시 사용자의 로컬 수정을 보존합니다.

이 검사는 호스트가 실제 요청에서 스킬을 자동 선택했는지까지 확인하지는 않습니다. 자세한 실행 방법은 [기여 안내](../CONTRIBUTING.md)와 [설치 안내](installation.md)에 있습니다.

## 스킬 유무 비교

[58개 합성 사례](../tests/cases.json)를 같은 요청·자료·모델·도구 조건에서 두 번 실행합니다. `without_skill`에는 요청과 원자료를, `with_skill`에는 동일 입력과 해당 스킬 패키지를 제공합니다.

```bash
python3 scripts/evaluate.py --run-dir eval-runs/my-comparison
```

기본 실행은 현재 Codex 로그인을 사용합니다. 전체 사례를 두 조건으로 실행하면 116개 작업 실행과 별도 판정 실행에 계정 사용량이 발생합니다. 모델은 `--model`, 판정 모델은 `--judge-model`로 지정할 수 있습니다. 필요한 사례만 확인할 때는 `--cases CASE_ID`를 사용합니다.

1. **입력을 고정합니다.** 실행 시작 시 스킬·참조·픽스처·평가 기준의 스냅샷과 해시를 저장합니다. 모델, reasoning effort, CLI, 날짜, Git 리비전과 미커밋 변경의 해시도 기록합니다.
2. **정답을 숨깁니다.** 실행 모델에는 요청한 픽스처만 제공하고, `criteria`는 주지 않습니다. 픽스처에는 저자 정보·참고문헌·결과 발췌·사용자 메모 같은 원자료를 남깁니다.
3. **실행을 분리합니다.** 각 조건은 새 프로세스와 임시 작업공간을 사용합니다. 호스트 스킬 자동 탐색, 플러그인·앱·메모리·웹 검색을 끄며, 외부 자료 조회 없이 제공된 합성 자료를 사용하도록 지시합니다.
4. **별도 판정으로 채점합니다.** 판정 실행에는 요청·원자료·실제 응답·생성 파일 목록과 내용·기준을 줍니다. 조건 이름과 스킬 지침은 숨깁니다. 판정에는 인용 근거와 이유가 필요합니다.
5. **누락을 성공으로 계산하지 않습니다.** 각 기준을 `pass`, `fail`, `unassessed`로 기록합니다. 실행 오류와 미완료도 확인합니다. 필요한 기준이 모두 `pass`인 경우만 사례 전체 통과로 셉니다.

조건 이름을 숨겨도 출력 형식으로 스킬 사용 여부를 추측할 수 있으므로 완전한 맹검은 아닙니다. 실행과 판정을 같은 모델로 하면 편향도 공유할 수 있습니다. 한 번의 출력은 모델·시점·도구에 의존하며, 다른 모델이나 실제 사용자에게 그대로 일반화할 수 없습니다.

### 비교를 수정하거나 재실행할 때

출력과 판정을 덮어써서 좋은 결과만 남기지 않습니다. 지침을 바꿨다면 새 실행 디렉터리를 사용하고, 이전 실패를 보존합니다. 같은 스냅샷의 중단된 작업은 같은 명령으로 이어갈 수 있습니다. 실행 자체가 오류로 끝났다면 기록을 보존한 새 디렉터리에서 재실행해 주세요.

`--reuse-baseline-from PREVIOUS_RUN`은 스킬이 없는 조건의 **요청·입력 파일·모델 설정이 동일할 때만** 이전 실행을 재사용합니다. 기준이 바뀌면 다시 판정하며, 요청이나 자료가 바뀌면 다시 실행합니다. 각 재사용에는 출처 기록이 남습니다.

특정 점수 척도처럼 스킬만 아는 형식은 일반적인 능력 비교의 정답으로 쓰지 않습니다. 양쪽에 같은 판단에 필요한 정보를 제공하고, 점수 합산·근거·결측 처리처럼 관찰 가능한 의미를 평가합니다.

## 무엇을 평가하나요?

- **읽기와 문헌 조사:** 초록만 읽은 한계, 정확한 인용 방향, 동명이인 구분, 버전·반대 근거·조사 범위를 포함한 종합을 확인합니다.
- **아이디어와 설계:** 근거 범위 안의 신규성, 공정한 비교, 질문을 구별하는 실험, 긍정·부정·모호한 결과에 따른 판단을 확인합니다.
- **Proposal과 스코어카드:** 주장과 근거의 연결, 핵심 결함, 산술, 미제공 자료의 미평가 처리, 문서 품질과 연구자 역량의 구분을 확인합니다.
- **목표 학회·저널과 미팅:** 연도·트랙·논문 유형, 공식 의무와 권고, 논의 가능한 초안과 과학적 준비도의 차이를 확인합니다. 픽스처 기반이므로 실제 학회 정책의 실시간 확인을 평가하지는 않습니다.
- **범위 유지:** 짧은 요약, 두 논문 비교, 검토만 요청한 작업에 전체 연구 과정을 강제하는지 확인합니다.

### 시각화는 별도로 확인합니다

텍스트 판정은 taxonomy의 분류 근거·관계와 실제 편집 파일의 존재를 확인할 수 있지만, 렌더링된 이미지의 가독성을 입증하지 못합니다. 시각 검사만으로 판단할 수 있는 기준은 `unassessed`로 둡니다.

계층형 taxonomy는 분류 기준·같은 수준의 형제·근거 있는 중복 소속을 확인합니다. 포스터는 원문과 그림의 주장·계획/결과 표기가 일치해야 합니다. 실제 렌더에서 잘림·겹침·글자 크기를 확인하고, PDF는 내보낸 파일의 페이지 수를 세어야 합니다. 생성 에이전트와 후속 검사자가 수행한 검증은 구분해서 기록합니다.

## 라우팅 회귀 평가

[48개 요청과 기대 스킬](../tests/routing.json)에는 7개 연구 스킬·사용 안내 스킬과 범위 밖 요청 `none`이 들어 있습니다.

```bash
python3 scripts/evaluate_routing.py --run-dir eval-runs/my-routing
```

모델에는 이름·description과 요청만 주며 기대 정답은 숨깁니다. 반환된 라벨을 정확히 비교합니다. 이는 description으로 작업을 구별하는 평가이며, Codex·Claude Code의 실제 자동 탐색이나 연구 작업의 실행 성공률은 아닙니다.

## 길이 제약 반복 검사

```bash
python3 scripts/evaluate_formats.py --engine codex --run-dir eval-runs/formats-codex
python3 scripts/evaluate_formats.py --engine claude --model sonnet --run-dir eval-runs/formats-claude
python3 scripts/evaluate_routing.py --engine claude --model sonnet --run-dir eval-runs/routing-claude
```

한·영 요청을 각각 스킬 유무 두 조건에서 3회 실행합니다. 12개 응답의 문장 수를 고정 규칙으로 세며, 모델 판정은 사용하지 않습니다. 이 분리 규칙은 해당 짧은 예제용으로 내용의 정확성을 채점하지는 않습니다. Claude Code 인증이 없으면 실행하지 않습니다. 두 엔진은 별도 실행이며 GPT 통과를 Claude 통과로 해석하지 않습니다.

## 실제 연구 유용성은 아직 별도 검증이 필요합니다

[공개 논문 예제](../examples/quantized-adaptation/README.md)는 의도한 결과를 보여주기 위해 검토·편집한 자료입니다. 독립적인 효과 측정이나 실제 실험 결과가 아닙니다.

실제 유용성을 평가하려면 같은 자료·모델·도구·예산으로 연구자가 작업한 결과를 비교해야 합니다. 주장 근거의 정확도, 잘못된 인용 연결, 실행 가능한 검증 계획, 연구자의 수정 부담과 결정 시간을 확인하는 것이 좋습니다. 핵심 결과는 연구자가 자신의 계획을 설명하고 방어할 수 있는지입니다.

초기 지침 비교에서 34개 중 28개는 양쪽 조건의 결과가 같았습니다. 회귀 사례를 효과 입증용 benchmark로 홍보하지 않으며, 새 자연어 사례도 개발용 회귀 검사입니다. 후속 효용 검증은 [사전 설계](evaluation-study.md)에 따라 아직 사용하지 않은 과제와 독립적인 평가자를 확보한 뒤 진행합니다.

전체 실행 기록은 기본적으로 Git에서 제외한 `eval-runs/`에 보관합니다. 공개 보고에는 공유 가능한 입력·출력·판정·한계를 포함하고, 미공개 원고나 인증 정보는 넣지 않습니다.

## 로컬 Claude 행동 비교

```sh
python3 scripts/evaluate.py --engine claude --model sonnet --run-dir eval-runs/claude-behavior --cases imprecise-null supported-equivalence proxy-construct bounded-measure guide-next-decision
```

`opus`로 별도 실행할 수 있습니다. 실행은 로그인된 Claude Code의 네이티브 CLI를 사용하고, 채점은 별도 Codex 프로세스가 기준만 보고 수행합니다. `--safe-mode`는 호스트 사용자 지침·스킬·플러그인을 끄며, 평가 스냅샷의 해당 지침만 프롬프트에 넣습니다. Claude 실행에는 Read·Glob·Grep·Write·Edit만 열려 있습니다. 셸·검색·PDF 렌더링은 제공하지 않으므로 이 경로를 렌더링 사례에 대한 검증으로 사용하지 않습니다.

모델 별칭과 CLI가 실제 보고한 모델 ID, 사용량, 시각, 지침 해시, 입력·출력·판정을 기록합니다. 스킬 사용 조건도 자동 선택이 아닌 지침 주입 검사입니다. 별도의 설치·명시적 호출 검사는 그 범위를 구분해 보고합니다. 판정 모델 역시 오류를 낼 수 있으므로 실패와 조건 간 차이는 원문으로 확인합니다.

이전 배포의 샌드박스 셸 경로는 `--claude-shell`로 선택할 수 있습니다. PDF 렌더링 등 로컬 실행이 필요한 사례에서만 사용하세요. 셸 샌드박스는 작업공간 밖 쓰기를 제한하지만 네트워크 차단을 보장하지 않으므로 외부 조회 금지는 지시로 유지됩니다. 서로 다른 도구 접근 조건의 baseline은 재사용하지 않습니다.
